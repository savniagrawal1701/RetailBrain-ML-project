      Teach a coupon agent when discounts are worth it

      Four customer types react differently to a discount. The agent starts knowing nothing, tries coupons, and learns who needs one. It plays against simple rules on the same simulated customers.

      Extra profit compared with giving no coupons, as customers arrive. Above zero beats doing nothing; below zero loses money.

      The store is simulated: there is no real coupon data in an Olist-style dataset, so each segment's response to discounts is set by hand. What is real is the learning: the agent only sees who bought, never the hidden rules.

      Under the hood Thompson sampling (a multi-armed bandit), compared with epsilon-greedy and fixed discounts.

      How it is built

      One fictional online store, one shared dataset, ten models that feed each other.

      Business questionAlgorithms
      How many days will this order take?Linear, Ridge and Lasso regression
      Will it arrive late?Logistic regression, compared with tree, forest and XGBoost
      Which rules explain late orders?Decision tree
      Will this customer buy again?Random forest and tuned XGBoost
      Was the review happy or angry?Naive Bayes on TF-IDF
      What types of customer do we have?K-Means on recency, frequency and spend, plus PCA
      What looks like this product?K-nearest neighbours
      What should we show this customer?Collaborative + content hybrid
      Who deserves a coupon?Thompson-sampling bandit
      How much will we sell next week?XGBoost versus a neural network

      The data is simulated to look like the Olist Brazilian marketplace (orders, delivery dates, reviews, repeat purchases), with cause and effect built in, so the numbers here are not results from a real store. The README explains how to swap in the real Olist files.
